# manic — персональная nail-студия

Рабочий фундамент сайта на **Next.js App Router, TypeScript и Tailwind CSS**. Все страницы экспортируются в статические файлы. Сервер приложения, база данных и платные API не нужны.

**Сейчас включён деморежим.** `manic` — рабочее название. В галерее — собственные векторные иллюстрации образцов, а не выполненные работы. Имя, цены, контакты, дипломы и отзывы не выдуманы: незаполненные сведения честно обозначены. Онлайн-запись не подключена. Индексация закрыта одновременно через robots и метаданные.

## Быстрый запуск

В Windows откройте PowerShell в папке проекта. В этой рабочей копии уже есть переносимый Node.js в `.tools`, он не меняет системные настройки:

```powershell
$env:PATH = "$PWD\.tools\node-v26.13.0-win-x64;$env:PATH"
$env:NEXT_TELEMETRY_DISABLED = '1'
npm.cmd run dev
```

Откройте **http://127.0.0.1:3000**. На Windows используйте `npm.cmd`, если политика PowerShell запрещает запуск `npm.ps1`. Альтернативный помощник: `. .\scripts\use-node.ps1`, если разрешено выполнение локальных скриптов.

На другом компьютере установите актуальный Node.js LTS, затем:

```sh
npm ci
npm run dev
```

Версии зависимостей зафиксированы в `package.json` и `package-lock.json`. `.tools` не нужна для размещения сайта и не включается в Git.

## Что работает

- Главная с услугами, информацией о мастере, FAQ, отзывами и контактами.
- `/portfolio/`: адаптивная галерея, фильтры по конфигурируемым категориям, просмотр изображений, выбор референса и отдельные ссылки на каждый дизайн.
- `/portfolio/<id>/`: статическая страница дизайна с тегами, связанными услугами и кнопкой записи. Несколько фото добавляются в `images`.
- `/quiz/`: три шага подбора по стилю, длине и оттенку. Все выбранные критерии должны совпасть; «не знаю» не ограничивает выбор. При отсутствии совпадений — честное пустое состояние.
- Выбор дизайна/услуги сохраняется в `sessionStorage` в пределах вкладки. При запрете хранилища работает в памяти. Данных о клиенте и истории визитов нет.
- Окно записи показывает выбранный референс, услугу и только заданные цену/время. Можно скопировать пожелания и ссылку; при запрете Clipboard API появляется поле для ручного копирования.
- DIKIDI, YCLIENTS или произвольный HTTPS-сервис подключаются одним конфигом. Нет собственного календаря и ложного подтверждения записи. «Записаться снова» ведёт через тот же адаптер.
- Общий доступ к сайту и дизайнам через Web Share или копирование ссылки; есть резервное поле, если API браузера недоступны.
- Мобильное меню, постоянная кнопка записи, клавиатурный фокус, skip-link, нативные диалоги с Escape, уменьшение анимации через `prefers-reduced-motion`.
- Серверные метаданные, Open Graph, favicon, sitemap, robots; JSON-LD с фактическими данными появляется только после прохождения проверки готовности.
- Подготовлена Метрика с согласием, отказом и отзывом согласия. По умолчанию отключена и не делает внешних запросов.

## Где менять данные

Все файлы — в **`src/content/`**. Меняйте данные, сохраняя структуру и типы.

| Файл | Что заполнить |
| --- | --- |
| `studio.ts` | Название бренда, имя, биографию, образование, фото, описание студии, фактический порядок обработки инструментов, FAQ |
| `contacts.ts` | Телефон в формате `+7…`, подпись телефона, Telegram/VK, реальный адрес, график, маршруты, фото входа, ссылки отзывов |
| `services.ts` | Услуги, категории, состав, дополнительные работы, `price` в рублях и `durationMinutes` в минутах |
| `portfolio.ts` | Категории, реальные работы, изображения, теги, связанные услуги |
| `reviews.ts` | Только настоящие отзывы с автором, датой и прямой ссылкой на источник |
| `diplomas.ts` | Только настоящие дипломы с разрешением на публикацию |
| `booking.ts` | Провайдер, HTTPS-ссылка записи, запасной мессенджер и его название |
| `seo.ts` | Домен, метаданные, реквизиты политики, ID и условия подключения аналитики |
| `types.ts` | Общая схема данных; отправная точка для будущей CMS |

### Фотографии и работы

1. Положите фото в `public/images/works/`. Рекомендуются WebP/AVIF шириной 1000–1400 px; сожмите их заранее и удалите ненужные EXIF-данные. Статический экспорт не запускает серверный оптимизатор изображений.
2. В `portfolio.ts` замените демозаписи. Пример структуры **с заполнителями, не реальными данными**:

```ts
{
  id: 'real-work-01', // только латиница, цифры и дефисы; не менять после публикации
  title: 'Название работы',
  subtitle: 'Оттенок · форма',
  images: [{ src: '/images/works/work-01.webp', alt: 'Описание настоящей работы' }],
  categories: ['nude', 'minimal'],
  styles: ['natural'],
  lengths: ['short'],
  shades: ['nude'],
  serviceIds: ['gel'],
  demo: false,
  // price и durationMinutes необязательны: неизвестное не заполняйте.
}
```

3. Свяжите `serviceIds` с `id` из `services.ts`. Категории добавляются в `categories`; значения стиля/длины/оттенка описаны в `types.ts`.
4. Замените `studio.portrait`, дипломы и фото входа. `hero.svg` — декоративная иллюстрация, она может остаться; подпись о её происхождении предусмотрена отдельно. При замене на фотографию обновите `alt` и подпись в `src/app/page.tsx`.
5. После изменения контента **пересоберите сайт**: файлы в `out/` не обновляются сами.

Шрифты хранятся локально в сборке, запросов к Google Fonts нет. Их лицензии включены в `public/licenses/`. `scripts/generate-demo-assets.py` воспроизводит собственные SVG-заглушки; не запускайте его поверх заменённых вручную файлов.

### Запись

В `booking.ts` укажите реальную ссылку из кабинета сервиса:

```ts
provider: 'dikidi', // также 'yclients' или 'custom'
url: '', // сюда HTTPS-ссылку вашей страницы записи
messengerLabel: 'Написать мастеру',
messengerUrl: '', // HTTPS-ссылка настроенного канала
```

Адаптер находится в `src/lib/booking.ts`, переиспользуемая кнопка — `BookingButton`. Никакой передачи пожеланий через недокументированные параметры нет. Посетитель сам вставляет скопированное описание в комментарий или сообщение. Переход в сервис и подтверждённая запись — разные события.

### Аналитика и UTM

В `seo.ts`: заполните `yandexMetrikaId`, подтвердите правовую готовность `legalReady`, оставьте `requireConsent: true`, затем включите `enabled`. Счётчик загружается только после явного согласия. Кнопка настроек позволяет отказаться; ранее загруженный скрипт удаляется перезагрузкой страницы. При недоступном localStorage счётчик не включается.

События: `booking_click`, `booking_outbound`, `quiz_start`, `quiz_complete`, `work_select`, `contacts_click`, `route_open`, `messenger_outbound`, `repeat_booking_click`, `share_click`. Цели нужно отдельно создать в Метрике. События подтверждённой записи здесь нет.

Вебвизор, карта кликов и автоматическое отслеживание ссылок отключены. Первичный просмотр отправляется без query-параметров. Страницы при клиентской навигации отдельно не отслеживаются; цели работают. Изменения конфигурации требуют пересборки и проверки настроек в кабинете Метрики.

UTM читаются в память вкладки и сохраняются при клиентских переходах. Внешней записи они передаются только при `forwardUtmToBooking: true`; разрешены исключительно пять `utm_*` параметров, каждый ограничен по длине. Полные URL и персональные данные в события не передаются. Примеры входящих ссылок:

```text
https://ваш-домен.рф/?utm_source=yandex_maps&utm_medium=profile&utm_campaign=studio
https://ваш-домен.рф/?utm_source=2gis&utm_medium=profile&utm_campaign=studio
https://ваш-домен.рф/?utm_source=vk&utm_medium=social&utm_campaign=portfolio
```

### Вторая локация и будущая CMS

Локации — массив `locations`. Добавьте Москву только после появления реального места приёма и заполнения адреса, графика и маршрутов. Отдельных вымышленных страниц городов нет.

Для CMS замените слой `src/content` на получение данных на этапе сборки с теми же типами. Компоненты, подбор и адаптер записи можно сохранить. Новый контент CMS должен вызывать пересборку статического сайта.

## Проверки и сборка

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm run preview
```

`preview` обслуживает **готовый `out/`** по адресу http://127.0.0.1:4173. Остановить сервер: Ctrl+C. Это локальная проверка, не публичное размещение. `next start` для `output: 'export'` не используется.

Тесты проверяют подбор, фильтры, ссылки, описание пожеланий, адаптер, безопасные URL, защиту публикации и целостность контента. Браузерная проверка — `scripts/browser-qa.mjs`; локальные инструменты QA находятся в игнорируемой `.tools/qa`, не входят в зависимости сайта. Подробности последней проверки — `VERIFICATION.md`.

Для повторения браузерной проверки на другой машине установите отдельные инструменты:

```sh
npm install --prefix .tools/qa --no-save playwright @axe-core/playwright
node .tools/qa/node_modules/playwright/cli.js install chromium
```

При работающем `npm run preview` запустите в другом терминале `node scripts/browser-qa.mjs`. В этой рабочей копии Chromium расположен в `.tools/browsers`: перед запуском задайте в PowerShell `$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD\.tools\browsers"`. Результаты и скриншоты сохраняются в `.artifacts/`; это папка локальной проверки. QA также воспроизводит `public/og.png` из HTML/CSS и локальных шрифтов.

Для публичной сборки:

```sh
npm run check:release
npm run build:release
```

Сейчас `check:release` **намеренно завершается с кодом 1** и перечисляет незаполненные данные. Обычный `build` разрешён для локальной демонстрации, но сохраняет запрет индексации. Проверка подтверждает заполненность конфигурации, а не достоверность сведений: её должен проверить владелец. Не обходите её ради публикации.

На российском статическом хостинге включите HTTPS, загрузите **содержимое `out/`** в корень сайта, сохраните каталоги и `_next/`. Настройте `index.html` внутри каталогов и свою `404.html`. Для nginx достаточно `try_files $uri $uri/ =404;` и `error_page 404 /404.html;`. Учитывайте правила конкретного хостинга. Деплой автоматической интеграцией с внешними платформами не настроен.

- [ ] Указать реальные цены или оставить честное «Стоимость уточняется»; согласовать состав услуг, длительность, доплаты и правила переноса.

- [ ] Заменить **сам текст** `src/app/privacy/page.tsx` на проверенную политику, убрать отметки шаблона и заполнители. Затем заполнить `seo.legal` и подтвердить `policyReviewed`.
- [ ] Проверить с профильным специалистом применимые обязанности по 152-ФЗ: статус оператора, основания и цели обработки, уведомления, локализацию, договоры с хостингом/сервисом записи/аналитикой, трансграничную передачу, сроки хранения и обращения субъектов. Этот проект не заменяет такую проверку.

- [ ] Поставить `studio.demo: false`, выполнить все проверки и `npm run build:release`.
- [ ] После размещения проверить все страницы, `robots.txt`, `sitemap.xml`, Open Graph, маршруты, телефон, мессенджеры и фактическую внешнюю запись.

## Архитектура

```text
src/app/          Статические страницы и метаданные App Router
src/components/  Интерфейс, доступные диалоги, подбор, запись, согласие
src/content/     Типизированные данные, подготовленные для CMS
src/lib/         Чистые функции, адаптер записи, события, готовность к запуску
public/          Локальные изображения и favicon
tests/           Тесты предметной логики
scripts/         Проверка публикации, preview и локальные инструменты
out/             Готовый результат npm run build (не редактировать вручную)
```

Стили и токены — в `src/app/globals.css`; CSS Tailwind подключён через PostCSS. Русский язык задан в layout. Тексты данных отделены от компонентов; для полноценной локализации понадобится вынести оставшиеся интерфейсные строки в словарь.

## Небольшой roadmap

1. Реальный контент, подключение записи, проверка юридических документов и статический запуск.
2. CMS на этапе сборки, локализация и дополнительная реальная локация.
3. Напоминания, повторные визиты и лист ожидания — сначала возможностями DIKIDI/YCLIENTS. CRM, кабинет, оплаты, рассылки и программа баллов требуют отдельного обоснования и в MVP не входят.
