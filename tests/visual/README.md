# Визуальные кандидаты

Статус: **CANDIDATE — не утверждённый дизайн**. Созданы 8 ноября 2026 года на Windows, Playwright/Chromium из lockfile, ru-RU, Europe/Moscow, light, reduced motion, высота 1000 px.

Активно сравниваются 88 PNG: 12 состояний на 7 ширинах и меню на 320/375/390/768 px. Текущие состояния: home, portfolio, work, privacy, missing, filter, viewer, quiz-focus-disabled, quiz-hover, quiz-result, booking-reference-wishes, quiz-empty. Прежние `booking-copy-error-*.png` оставлены историческими: старое окно удалено из пользовательского пути и эти снимки больше не сравниваются.

Снимки фиксируют демосайт с неизвестными ценами и прямой записью в DIKIDI. На прежнем этапе записи были изменены только 39 связанных PNG; остальные 49 тогда сохранялись.

На текущем UX/UI-этапе пользователь явно запросил общую доработку типографики, отступов, шапки, карточек, адаптивных сеток и элементов управления. Эти общие стили намеренно затронули все 88 активных состояний. После сравнения со старыми кандидатами выбран для обновления именно активный набор `tests/visual/site.spec.ts`; 7 исторических booking-copy-error не обновлялись. Причины и список компонентов — `docs/UX_UI_REPORT.md`. Обычные прогоны PNG не меняют.

Повторное строгое сравнение выявило настоящий дефект колебания высоты шапки на tablet: исправлен раздельными порогами прокрутки, добавлен regression test. Перед full-page снимком страница возвращается наверх; перед element capture ожидаются кадры после scrollIntoView, чтобы изменение шапки не меняло координаты обрезки. После просмотра отдельно скорректированы только 7 viewer и quiz-hover-768: прежние кандидаты были сняты до стабилизации прокрутки (края диалога и субпиксельные края иконок). Перед viewer фон страницы теперь всегда возвращается наверх; это устраняет зависимость полупрозрачных краёв клипа от случайной позиции фона. Порог сравнения не увеличивался, маски не добавлялись.

Выборочно просмотрены hero desktop/mobile, portfolio, service rows, viewer, quiz result и диффы. Это проверка агентом, а не общее утверждение всех размеров и дизайна владельцем. Фактический результат обычного сравнения после генерации — в `docs/QA_REPORT.md`.

В завершении доработки заданы целые line-height для логотипа и демоплашки: повторные снимки показывали 529 отличающихся пикселей только в логотипе после sticky-прокрутки. До этой правки у шапки и логотипа были дробные координаты. Правка слегка меняет вертикальные размеры общей шапки/логотипа; активные кандидаты обновлены отдельно, а итоговый запуск снова выполняет строгое сравнение без записи PNG.

Обычный `test:visual` сравнивает строго и не записывает PNG. `test:visual:candidates` создаёт только отсутствующие кандидаты. Не обновляйте существующие снимки без установленной причины, анализа diff и согласованного изменения. Для другой ОС нужны собственные кандидаты.

Порядок просмотра/обновления: `docs/TESTING_GUIDE.md`. Текущее сравнение и найденные проблемы: `docs/QA_REPORT.md`.
